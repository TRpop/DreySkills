# 기획 합의

> obra/superpowers 의 brainstorming 스킬(MIT, Jesse Vincent)을 쉬운 말로 줄여 옮김.

**사용자 OK 를 받기 전에는 만들지 않는다.** 코드·파일 만들기, 프로젝트 뼈대, 설치 모두 "만들기"다. 읽고 살펴보는 것은 된다.

## 쓰지 않을 때
- **하위 세션**(기획자가 `agent_delegate` 로 맡긴 일)은 이미 승인된 일이다. 사용자와 다시 합의하지 않고, 범위 쟁점은 결과로 기획자에게 한 번 돌려준다.
- 사용자가 이미 승인한 범위(이 대화·plan·기획서·승인된 업무에 있는 것)는 질문·선택지·OK 를 다시 밟지 않는다. 그 범위 안의 세부 결정은 정하고 알린다.
- 사용자가 "묻지 말고 그냥 해"라고 하면 정한 방법을 한 줄로 알리고 바로 한다. 버려도 되는 시험 삼아 만들기(스파이크)를 사용자가 좋다고 했으면 그것만 만든다 — 그 결과를 살려 쓰는 것은 다시 합의.

## 1. 먼저 알아보기
- plan 은 `work_plan_read` 로 관련 칸만(도구가 없으면 `docs/drey/plan.md`), 업무는 `work_docs_read {"view": "brief"}` → 관련 번호만, 그리고 이 일이 건드릴 파일을 본다. 읽으면 알 수 있는 것은 묻지 않는다.
- 업무 분야(개발·문서·조사·범용)에 맞게 생각한다 — 문서·조사 일에 빌드·시험·배포 절차를 끌어오지 않는다.

## 2. 필요한 것만 묻기
- 요청을 내 말로 짧게 되짚고(무엇을, 누구를 위해, 왜), 찾은 것(지금 상태, 바뀌는 것, 사용자가 모를 만한 걸림돌)을 덧붙인다.
- 결과를 크게 바꾸는데 읽어서 알 수 없는 모호함이 있을 때만 묻는다. 한 번에 몇 개만(되도록 하나), 왜 묻는지 한 마디. 고를 것이 분명하면 질문 카드(AskUserQuestion)를 쓴다.
- 정보가 충분하면 묻지 않고 바로 추천·기획안(3·4)으로 간다. 내가 정한 기본값은 숨기지 않고 "(제안)"으로 밝힌다.
- 살펴볼 거리(필요한 것만): 목표·하지 않을 것·이러면 실패, 이미 있는 것·해 본 것, 사용자가 신경 쓰는 세부.

## 3. 선택지와 추천
- 방법 사이에 실질적인 선택(얻고 잃는 것이 다름)이 있을 때만 2~3개를 비교하고 **추천 하나와 이유**를 댄다. 사실상 하나뿐이면 그 방법과 이유만 말한다.
- 질문·비교·기획안을 따로 나눈 메시지로 보낼 필요는 없다 — 한 답에 함께 둘 수 있다.
- 보는 게 빠른 것(화면·배치·흐름)이면 목업(라이브 데모)을 제안할 수 있다. 좋다고 하면 out/ 에 HTML 로 만들고 상대 경로를 알린다.

## 4. 적기
- 방법이 정해지면(사용자가 고르거나 추천 하나뿐이면) 일의 크기를 한 줄로 말하고 적는다(작업 규칙이 없으면 답에만):
  - plan 에는 짧은 항목만 — 목표·범위·제약·확정 결정(`YYYY-MM-DD 고른 방법 — 이유`)·열린 질문. `work_plan_update` 로 항목만 더하고, 정해진 열린 질문은 결정으로 옮긴다(인자는 도구 설명으로 확인). 긴 배경·비교·완료 기준 상세는 docs/ 의 기획서에 두고 plan 에서는 경로로 가리킨다.
  - 사용자가 말한 것과 내가 채운 것("(제안)")을 구분한다.
  - 사용자 답을 기다리는 결정안은 planning 업무를 `승인 대기`·`확인 주체: 사용자` 로.
- 목표·완료 기준을 답에 보여 주고 **"이대로 시작할까요?"** 로 묻고 멈춘다.

## 5. OK 뒤
- 같은 뜻의 업무는 번호를 유지해 worklist 로 옮긴다(`work_task_move`). 기획 업무를 끝내고 실행을 따로 나눌 때만 기획 업무를 합의로 완료하고 새 번호로 실행 업무를 만들어 `먼저` 로 잇는다. 형식·완료 방식은 스킬 `update-docs`.
- "좋아요"는 보여 준 것에 대한 OK 다. 보여 주지 않은 것까지 합의된 것은 아니다.

## 다시 합의
- 일하다 목표·완료 기준이 바뀌어야 하거나, 일이 커지거나, 여러 독립된 일임을 알게 되면 **멈추고** 그렇게 말한 뒤 바뀐 부분만 이 순서로 다시 합의한다(하위 세션은 기획자에게 돌려준다).

## 이러면 잘못 가는 중
- 요청이 모호한데 짐작으로 선택지를 늘어놓는다 → 결과를 바꾸는 점 하나를 먼저 묻는다.
- 읽으면 알 수 있는 것·이미 답한 것을 묻는다 → 묻지 말고 추천으로 간다.
- "좋네요"라고 했으니 만든다 → 새 목표·완료 기준을 보이고 OK 를 받았나?
- 이미 승인된 일을 다시 묻는다 → 승인 범위를 확인하고 진행한다.
