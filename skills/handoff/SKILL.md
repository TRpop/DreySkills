# 인수인계

- `docs/drey/` 가 없으면 "작업 규칙이 아직 없습니다 — ⋯ 메뉴의 작업 규칙 만들기로 만들 수 있어요"라고 알리고 멈춘다.
- **하위 세션**은 handoff.md 를 쓰지 않는다(정본은 기획자만). 자기 결과·남은 일을 마지막 답으로 기획자에게 돌려준다.
- 단계 문서·plan 을 먼저 일괄 정리하라고 요구하지 않는다. 업무 상태는 단계 문서가 정본이므로 handoff 에는 번호와 근거 링크만 두고 내용을 복제하지 않는다.

`docs/drey/handoff.md` 를 아래 모양으로 **새로 쓴다**. 이미 있으면 지난 것은 맨 아래 "지난 기록"에 날짜와 한 줄만 남긴다.

```markdown
# 인수인계

쓴 날: <YYYY-MM-DD>

## 지금 상태
- 무엇이 되고 무엇이 안 되는지 (확인한 방법과 함께, 미확인은 미확인으로)

## 이어서 할 일
- 업무 번호와 제목만 (진행·예정·사용자 확인 대기)

## 대화에서만 나온 것
- 알아낸 빌드·실행 방법, 사용자가 말로 정한 것, 함정·임시 처리 — 단계 문서·plan 에 이미 있으면 쓰지 않는다

## 먼저 읽을 것
- 파일·문서 경로 몇 개

## 지난 기록
- <날짜> <한 줄>
```

다음 세션은 이전 대화를 모른다 — 문서에 없는 것만 남긴다. 비밀번호·키·개인정보는 쓰지 않는다. 다 쓰면 "handoff.md 를 썼습니다"와 이어서 할 일 개수를 알린다.
