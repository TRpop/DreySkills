# 도구 없이 만들 때

정말 옛 앱이라 `work_docs_setup` 같은 도구도 `DreyBrowser.Mcp.exe --drey-docs` 명령도 없을 때, 없는 부분만 이 틀로 쓴다. plan 에 `계약:` 줄이 있는 공간이면 쓰지 말고 도구 상태(미확인이면 미확인)와 세션 재열기를 알린다. 쓴 뒤 검사 명령이 있으면 `DreyBrowser.Mcp.exe --drey-docs check .` 로 검사한다. 나중에 도구가 생기면 `work_docs_setup` 으로 원문을 보존한 채 이어 정비한다.

## plan.md
짧은 지도만 둔다. 업무 상세·실행 기록은 단계 문서에.

```markdown
# 계획

상태: 기획 합의 전

## 목표
- <사용자가 쓴 목표 — 말을 살려서>

## 범위
- <하는 것 · 하지 않는 것>

## 제약
- <지켜야 할 것>

## 확정 결정
- <오늘> 작업 규칙 만듦

## 열린 질문
- <아직 정하지 않은 것 — 없으면 비워 둠>
```

## 단계 파일
업무 번호 앞 글자는 대문자 약자(정하지 않았으면 `T`), 뒤는 세 자리 이상. 새 번호는 다섯 파일에 있는 가장 큰 번호 다음.

```markdown
# 기획

형식: drey-tasks/1
단계: planning
상태: 기획 합의 전

### T-001 | 기획 합의
- 유형: 기획
- 상태: 승인 대기
- 확인 주체: 사용자
- 먼저: 없음
- 요약: 배경·목표·완료 기준 합의

#### 상세
배경·목표·완료 기준을 plan.md 에 적고 사용자 OK 를 받는다.

#### 완료 기준
- [ ] 사용자가 plan.md 의 목표·완료 기준에 OK 한다.
```

worklist.md·done.md 는 머리만 두고 시작한다(`단계: work` / `단계: done`, `상태:` 한 줄). 다른 단계 파일은 쓸 업무가 생길 때 만든다. 업무 칸과 상태 값은 스킬 `update-docs` 의 [형식 참고](../../update-docs/references/manual-format.md)를 따른다.
